# 音叉

在浏览器里判断一首歌的基准音更接近 **432 Hz** 还是 **440 Hz**。如果是 440 Hz，可以转成 432 Hz 播放或下载，也可以对正在响的声音实时降频。

音频不会上传。分析和变调都在你的设备上完成。

## Windows 程序

双击「音叉.exe」即可，不用安装 Node。程序在解压后的整个文件夹里，不要把 exe 单独拷走。第一次打开如果 Windows 提示已保护你的电脑，点「更多信息」，再点「仍要运行」。

自己打包：

```bash
npm install
npm run pack:win
```

压缩包在 `release/音叉-Windows.zip`。

## 运行

```bash
npm install
npm run dev -- -p 3847
```

打开终端里打印的本地地址。测试：

```bash
npm test
```

## 怎么判断

一首按十二平均律演奏的曲子，所有音相对音格的偏差是一样的。A4 = 440 Hz 时，这个偏差接近 0。A4 = 432 Hz 时，全体大约偏低 31.8 音分（半音的三分之一左右）。

程序会在歌曲里较清楚的片段上做频谱峰值检测，把每个峰换算成相对 440 Hz 音格的音分，再看它们堆在哪里：

- 堆在 0 音分附近：判定为 440 Hz
- 堆在 −32 音分附近：判定为 432 Hz
- 音高太散，或落在两者中间、两边都不像：不做勉强判定

页面上的「440 Hz 示例」和「432 Hz 示例」是同一段 A 大调短句，只是基准音不同，可以先用来核对判断。

## 怎么播放

判定为 440 Hz 时，播放器会自动选中「432 Hz」。

- 默认连同速度一起变化，比例是 `432 / 测得基准音`。440 Hz 的曲子大约放慢 1.8%，没有变调算法带来的失真。
- 打开「保持原速」后，只移动音高，歌曲长度不变。第一次播放前需要先转换。

如果判断不确定，仍可以按标准的 440→432 比例（−31.8 音分）试听。

## 下载

准备好的歌曲可以「下载 432 Hz」。文件是 16-bit WAV，音高已经写进采样，用任何播放器打开都是 432 Hz。

- 默认和试听一样，音高与速度一起变化，440 Hz 的曲子大约长 1.8%。
- 打开「保持原速」后，只移动音高，长度与原曲相同。

## 实时降频

「全局降到 432 Hz」给听歌用。它假定歌曲是 440 Hz，打开后立刻降低，不再先听 8 秒。实时处理只保留一路声音，不会把一段延迟复制叠上去，所以没有双延迟造成的混响。

也可以先听大约 8 秒，判断这段声音的基准音，再按测得的比例降频。

- **用麦克风听**：先确认戴着耳机。分析时如果走扬声器，麦克风和喇叭会啸叫。
- **听电脑正在放的声音**：在 Chrome 或 Edge 里分享标签页并勾选音频，或分享带系统音频的屏幕。分享开始后，这段声音改由页面播放并降频。Windows 程序使用不静音的系统回环，避免把本程序自己的播放也关掉。
- **QQ音乐 / Edge**：Windows 程序里点「开始」。需要已安装 VB-CABLE。QQ音乐、Edge 和 Chrome 只在降频这一轮进入 CABLE Input，音叉听 CABLE Output，再从耳机（插着时）或外放播出，插拔会自动跟着换。切歌或大约每 3 分钟会再听一次。开始前，原来的声卡设置先记到本地；点停止或退出后按记录还原并核对。音叉意外关掉或断电时，下次打开或开机登录会自动复原。只关掉播放器不会结束这一轮。
- **整台电脑**（其他播放器）：把系统播放设到虚拟声卡（Windows 的 VB-CABLE，macOS 的 BlackHole），再在这里用麦克风选那条虚拟输入。

已经接近 432 Hz 时不再移动音高。判断不稳定时，按标准的 440→432 比例降频。
